## Inspection and code
Inventory every project area initially. Before a major change or test cycle, inspect affected source, imports, callers, schemas, migrations and tests. Do not repeatedly read every binary/cache/file in the repository. Preserve unrelated edits. Separate routes, domain services, adapters, repositories, ML features, UI and configuration. No monolithic app/page containing all features. Create directories only when they hold real files.

Use real integrations and explicit capabilities. Fixtures are allowed only in a visibly labeled demo/test mode; no silent synthetic fallback. A missing integration is unavailable, never falsely successful. Loading/empty/stale/error/partial/success states are required. UTC internally, labeled IST display. Validate requests, units, geo bounds and ownership on the server. Never expose API keys to the browser. Saved places and alerts require tested per-user ownership; no user-ID header shortcuts in production. Escape popup content and avoid logging sensitive profiles.

## Model and scientific integrity
Reuse and audit supplied models before retraining. Reconstruct exact preprocessing, feature order, timestamp meaning, target transform and supported horizons. Custom class source is needed for reliable full-pipeline loading. No invented class, arbitrary feature zeros, duplicated fake hourly predictions, fabricated accuracy/confidence, or unvalidated pollutant outputs. Read docs/MODEL_INTEGRATION.md. Route estimates and weather perturbations must communicate their method and limits. Health content is educational; no disease diagnosis or source-apportionment percentages without appropriate evidence.

Test meaningful risks: model parity and feature order, issue-time availability, units, target inversion, capability errors, API validation, persisted ownership, alert idempotency, spatial support, provider failures, and browser journeys. Run appropriate lint/type/build/tests and browser checks. Record command, result and material limitations; never claim a skipped check passed. PRD acceptance must be traced to evidence. A feature is done only when its full workflow works with real supported inputs or is explicitly recorded as blocked/unavailable. Final delivery must list remaining blockers, never imply all requirements are complete when some are gated.
